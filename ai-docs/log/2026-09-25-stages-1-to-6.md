# 2026-09-25: modernization stages 1 to 6 done as 2.1.0

Executes every stage of [the modernization plan](../plans/modernization-plan.md) in one pass. Committed and pushed to master the same night (commits 4228003, b28b6c8, aac63f3), CI green on Ubuntu and Windows, tagged v2.1.0; verification below was run locally on Windows with SDK 10.0.401.

## What changed

- **Data.** 49 Puerto Rico place names carried U+FFFD (Latin-1 file read as UTF-8); hand-fixed from the known Census 2000 spellings (`Bayamón`, `Mayagüez`, `Río Cañas Abajo`, ...). Place file deduplicated: 25,375 rows to 16,873 distinct names, 256 KB to 181 KB. `.gitattributes` keeps `*.stripped` LF.
- **Runtime.** `BaseNameGenerator`: `Random.Shared` on net6+, process-wide seeded source on netstandard2.0 (fixes GitHub issue #7, which the reporter had closed themselves in 2022 after a workaround); `using` on the resource stream; `InvalidOperationException` naming a missing resource; null check moved into the base constructor. Lists are `static readonly Lazy<string[]>`, parsed on first use. Place extensions gained the null and negative guards.
- **API (additive).** `PersonNameGenerator(int seed)`, `PlaceNameGenerator(int seed)`; static `IReadOnlyList<string>` properties `MaleFirstNames`, `FemaleFirstNames`, `LastNames`, `PlaceNames`. The interfaces were left unchanged on purpose: adding members to an interface breaks implementers and mocks. The six copy-pasted loops collapsed into one `Generate(count, pick)`. `BaseNameGenerator` is `EditorBrowsable(Never)`; `CensusListStripper` and `FileCompressor` are `[Obsolete]` pointing at `tools/CensusTools`, and the `IndexOf` returning -1 bug in the stripper is fixed in both copies.
- **Build.** Nullable, `TreatWarningsAsErrors`, .NET analyzers at latest, `IsTrimmable`/`IsAotCompatible` on net10.0, package validation against 2.0.1, XML docs on all 73 members (packed .xml is 27 KB, was 151 bytes), icon, copyright range, `global.json`, `Directory.Build.props` with lock files, `.editorconfig`, `CHANGELOG.md`, version 2.1.0.
- **CI.** Ubuntu and Windows matrix (Windows also runs net48 tests against the netstandard2.0 build), locked-mode restore with NuGet cache, concurrency cancel on PRs, `dotnet format --verify-no-changes` on Linux, cobertura coverage artifacts, Dependabot, tag-equals-version check, GitHub Release with the packages via `softprops/action-gh-release@v2`.
- **Tests.** 46 tests, all passing on net10.0 and net48: resource integrity (counts, blanks, U+FFFD, duplicates, Title case, accents), seed determinism, list membership per gendered method, zero and negative counts, null `Random`, tight-loop non-repetition (issue #7 regression), extension parity with the generators.

## Dead ends and gotchas

- MSBuild rejects `--` inside an XML comment in `Directory.Build.props` (`MSB4024`); write "locked mode" instead of `--locked-mode`.
- The Write tool on this machine writes CRLF without BOM; the repo's `.cs` files were BOM + LF. Normalized to LF, no BOM, after writing; `.gitattributes` `text=auto` makes the index LF either way.
- The README example rows for female, male and last names did not reproduce from a single `GenerateMultiple...(8)` call with `new Random(20260924)`; the rows were regenerated with that exact recipe and the README now states it. The place row changed anyway because the list changed.
- Puerto Rico names keep the `zona urbana` / `comunidad` suffix while other places lost their classification word. Left as is (README documents it); noted as a 3.0 decision in the plan.

First CI run failed with NU1004: NuGet on both runners evaluated the test project as net10.0 only while the lock file had net10.0 and net48; not reproducible locally, even with CI=true and GITHUB_ACTIONS=true and a clean obj. Root cause, found on the second and third runs: the lock file was generated on Windows, where the SDK gives a .NET Framework exe a default `win-x86` RuntimeIdentifier and resolves net48 from the installed targeting pack; on Linux the project had no RID and pulled Microsoft.NETFramework.ReferenceAssemblies implicitly, so the lock differed. Fix: reference Microsoft.NETFramework.ReferenceAssemblies explicitly and pin `RuntimeIdentifier win-x86` (with `SelfContained false`) for net48 in the test csproj. Rule: a locked-mode lock file for a multi-OS matrix must not depend on anything the SDK infers per OS.
